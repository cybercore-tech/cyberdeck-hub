01 / The tool board

Every light
tells the truth.

Each tool gets a cheap live probe matched to what it actually is, refreshed every few seconds. A security check counts as healthy when its timer is scheduled — not merely because a binary was built once.

PortWeb services: TCP connect to 127.0.0.1:PORT. ONLINE / OFFLINE.
SystemUnitsystemctl is-active for daemons and timers.
AnySystemUnitUp if any of several exclusive units runs — VortexWall's dry-run or enforce unit.
UserUnitsystemctl --user is-active for session services.
BinaryCLI tools with nothing to run: is it installed?
  • Quick options on every card: open the service, jump to its Cybercore Wiki page, see where its repo lives.
  • Real repo paths: a card shows ~/Devspace/Cybercore/<category>/<tool> when that's where the repo actually is.

03 / Setup

Boot
the deck.

The hub serves its web assets and reports relative to its repo, binds to loopback only, and takes its port from CYBERDECK_PORT. It never starts or stops anything — probes only ask.

BUILD + RUN 
git clone https://github.com/cybercore-tech/cyberdeck-hub
cd cyberdeck-hub && cargo build --release
sudo pacman -S lshw pciutils usbutils lm_sensors iproute2

CYBERDECK_PORT=8080 ./target/release/cyberdeck_core
# → http://127.0.0.1:8080
AS A HARDENED SERVICE (EXCERPT) 
[Service]
User=youruser
WorkingDirectory=/path/to/cyberdeck-hub
Environment=CYBERDECK_PORT=8080
ExecStart=/home/youruser/.local/bin/cyberdeck_core
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/path/to/cyberdeck-hub
CapabilityBoundingSet=
