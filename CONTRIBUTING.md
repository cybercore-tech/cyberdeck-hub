# Contributing Guidelines

Thank you for your interest in contributing. To maintain high code quality and smooth project operations, please review and follow these standards.

---

## 1. Community & Behavioral Expectations

This project operates on technical competence, direct communication, and mutual respect. 
* **Focus on the Work:** Keep discussions objective, technical, and centered on code architecture and performance.
* **Professional Conduct:** Personal attacks, toxic behavior, or disregard for project standards will not be tolerated.
* **Accountability:** Be prepared to justify your implementation decisions with sound technical reasoning.

For full behavioral guidelines, see the [Code of Conduct](CODE_OF_CONDUCT.md).

---

## 2. Submitting Issues and Pull Requests

### Creating Good Issues
Before opening a new issue, search existing tickets to prevent duplicates. When filing an issue, provide:
* **Clear Description:** A concise explanation of the bug, feature request, or system bottleneck.
* **Reproduction Steps:** Exact steps or commands required to reproduce the issue (if applicable).
* **Environment Details:** Relevant operating system versions, dependency versions, or configuration parameters.

### Creating Good Pull Requests (PRs)
* **Scoped Changes:** Keep PRs focused on a single objective or fix. Do not bundle unrelated changes.
* **Commit History:** Maintain a clean, logical commit history with descriptive commit messages.
* **Testing:** Ensure your changes compile cleanly without warnings or errors, and test locally before submission.
* **Code Style:** Match the existing codebase style, idioms, and architectural patterns.
